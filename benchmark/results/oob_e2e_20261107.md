# OOB 回连端到端实测（2026-11-07）

## 结论

**盲打 OOB 链路端到端成立**：扫描器注入带唯一 token 的 blind 载荷 →
目标渲染 → 资源被加载 → self-hosted 监听收到回连 → 归因为
**`blind / high / oob-confirmed`**。

这是"最高标准"五项基线里此前唯一**有代码但未验证**的一项，现在有了
真实 HTTP 回连证据。

## 方法

| 组件 | 配置 |
|---|---|
| OOB 监听 | `--oob self --oob-host 127.0.0.1 --oob-port 18999 --oob-timeout 15` |
| 靶点 | `127.0.0.1:18998/echo?q=` 原样反射；**从反射内容里正则提取 `http://127.0.0.1:18999/...` 并真实 GET**，模拟受害者浏览器加载注入资源 |
| 扫描 | `xsx.sh -u http://127.0.0.1:18998/echo?q=x --oob self ... -o - -f json` |

## 结果

```
rc=0  报告 20971 B  requests=20  1.39s
count 2
  reflected | high | browser-unavailable | param q
  blind     | high | oob-confirmed       | param q
    detail: Blind XSS CONFIRMED via out-of-band callback. The injected
            payload beaconed to the callback host ('self-hosted'); a
            victim's browser executed it, proving the input renders in an
            executable context ...
```

同一次扫描里两条证据类并存，正好演示了分级：
`reflected` 只到 `browser-unavailable`（未开浏览器），`blind` 到
`oob-confirmed`（回连是执行的最强旁证）。

## 边界（不夸大）

- **触发者是我写的模拟靶点**（服务端代浏览器加载资源），不是真实管理员/
  受害者浏览器。回连本身是真实 HTTP 请求，token 归因、`collect_oob`、
  finding 归因全部走产品代码。
- 监听与靶点都在 loopback，未测公网 `--oob-host` / NAT 场景。
- `interactsh` 后端未测（需要外网）。

## 复现

```bash
# 1) OOB 靶点（模拟受害者加载）
python <TEMP>/oob_target.py            # 127.0.0.1:18998
# 2) 带监听扫描
bash <TEMP>/xsx.sh -u 'http://127.0.0.1:18998/echo?q=x' \
  --oob self --oob-host 127.0.0.1 --oob-port 18999 --oob-timeout 15 \
  -o - -f json
```

原始产物：`oob_scan.json` / `oob_scan.err`（`xss_agent_e2e_20261107/`）。
