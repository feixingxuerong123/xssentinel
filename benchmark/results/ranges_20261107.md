# 五靶场实测（2026-11-07，本地）

## 结论

**sync 引擎在 5 个靶场 50 个用例上：TP31 / FP0 / TN19 / FN0 / SKIP0 / ERR0，
5 个 gate 全部 exit 0。** range3 的 async 引擎另行跑了一轮：TP17 / FP0 / TN7 /
FN0 / SKIP2（2 例 manifest 标 sync-only）/ ERR0，gate exit 0。

需要浏览器证据的正例全部拿到 `browser-confirmed`（range4 2/2、range5 1/1、
range7 的 dom/json 两例），不是"静态命中就算过"。

## 逐场结果

| 靶场 | 引擎 | TP | FP | TN | FN | SKIP | ERR | gate |
|---|---|---|---|---|---|---|---|---|
| range3（应用型：会话/存储/载体） | sync | 19 | 0 | 7 | 0 | 0 | 0 | exit 0 |
| range3 | async | 17 | 0 | 7 | 0 | **2** | 0 | exit 0 |
| range4（React/Vue 真实框架 sink） | sync | 2 | 0 | 2 | 0 | 0 | 0 | exit 0，正例 `browser-confirmed=1` |
| range5（Lit unsafeHTML） | sync | 1 | 0 | 1 | 0 | 0 | 0 | exit 0，正例 `browser-confirmed=1` |
| range6（sanitizer 版本对） | sync | 1 | 0 | 1 | 0 | 0 | 0 | exit 0 |
| range7（8 对正负，多载体） | sync | 8 | 0 | 8 | 0 | 0 | 0 | exit 0，正例 `browser-confirmed` |

合计：**sync 31 TP / 0 FP / 19 TN / 0 FN**；async（仅 range3）17 TP / 7 TN / 2 SKIP。

## 覆盖到的能力面（range3 明细）

正例全部 TP：`q-raw`（普通反射）、`multictx`（同页多反射点）、`rcdata`
（RCDATA 渲染）、`attr`（属性上下文）、`path`（路径段注入，11 findings）、
`header`（header 反射）、`cookie`（cookie 载体回显）、`b64`（base64 容器）、
`jwt`（JWT 容器）、`dom`（DOM 动态，4 findings，fired）、`cspnonce`
（CSP nonce 链）、`upload`（上传文件名/内容）、`stored`（存储型）、`so2`
（二阶流）、`auth-q`（认证后反射）、`xss-medium` / `xss-high`（分级防御）、
`utf7`（UTF-7 旧字符集）、`scenario-msg`（场景 DSL）。

负例全部 TN：`impossible`（DVWA 式 impossible）、`escaped`（实体化）、
`scare`（看起来危险但不可执行）、`cspstrict`（严格 CSP）、`static`
（静态无反射）、`unauth`（未认证 401）、`json-echo`（JSON 回显）。

## 判定口径（避免把审计类误读成 FP）

- **safe → FP 的判据**：`severity in (high, medium, critical)` 且
  `type` 不以 `csp_` / `trusted_types_` 开头（`range7/runner.py:111-124`；
  range6 只排除 `csp_`，range3 同）。
- 因此 `r7-neg-json` 的 `trusted_types_no_policy/medium`、range6 负例里的
  `sanitizer_*`/`trusted_types_*` **不算 XSS 误报**——它们是安全审计类提示，
  不是"这个参数可注入"。`r6-neg-dompurify-3417` 的 4 条全是 `low`，
  `low` 一律不进告警，所以判 TN 正确。
- range3 另有一类 `gt=low`：JSON body 里的反射**必须保留但 confidence=low**；
  命中且 confidence 不是 low 反而算 FP（`range3/runner.py:206-211`）。

## 证据归属与边界（不夸大）

- 全部是**本仓库自建靶场**，不是第三方真实应用；相比"自编 194 例矩阵"多了
  应用形态（会话、SQLite 持久化、混合 Content-Type、载体编码），但仍是
  "自己出的题"。
- **async 只跑了 range3**；range4/5/6/7 的 async 未跑。
- **未跑**：自编 194 例全量矩阵（`benchmark/run_benchmark_batched.py`）、
  XSSMaze 第三方靶、DVWA/bWAPP/Juice（需 Docker）。
- 本轮按引擎分命令跑（sync 与 async 分开），原因是本机每 agent turn 有
  50 次文件删除/覆盖配额，50 例一次跑完的临时产物清理容易触顶。
- 环境：`.venv` Python 3.12.10；Playwright Chromium **156.0.8078.4** 可用；
  `NO_PROXY=127.0.0.1,localhost`；端口由各 runner 自己探测（本次为
  18702 / 19704–19707，未撞占用）。
- `range4/5/6/7` 的 runner 把打分产物写回各自 `results.json`（仓库内既有路径，
  本轮同步更新，`git status` 显示这 4 个文件为 M）；`range3/runner.py` 的
  `--output` 默认 None，只打印不落盘，本轮没有改动仓库文件。
